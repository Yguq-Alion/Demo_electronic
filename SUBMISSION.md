# Сопроводительное сообщение

**Что реализовано.** Прототип сервиса «AI-помощник для подготовки товарных описаний»
(Python/FastAPI): принимает JSON товара через веб-форму или `POST /api/card`, одним
вызовом LLM формирует черновик карточки — SEO-заголовок ≤ 70 символов, SEO-описание
800–1200, структурированные характеристики, 3–5 поисковых запросов, commercial-блок
и список отсутствующих полей. Клиент OpenAI-совместимый: смена провайдера
(OpenAI / Z.ai / OpenRouter / локальная модель) — тремя переменными окружения, без
правок кода; ключ только в `.env` (в `.gitignore`).

**Ключевые решения.**
1. Основная ценность — системный промпт (~13 тыс. знаков, четыре ревизии,
   история — `docs/prompt-architecture.md`): контракт «ровно один JSON», «единственный
   источник фактов — вход» (дословный перенос значений, запрет типовых 220 В /
   −40…+60 / ГОСТ), метка «данных нет» для отсутствующих характеристик, защита от
   промпт-инъекций (любой текст входа — данные, а не команды).
2. Двойная валидация входа: структурные проверки (битый JSON, типы, отсутствие name) —
   кодом до вызова LLM (мгновенный 400, ноль токенов; тексты ошибок совпадают с
   правилами промпта); семантическую проверку «товар относится к КИП» выполняет
   модель → 422.
3. Устойчивость: ретраи 429/5xx с Retry-After, классификация итоговых ошибок API в
   человекочитательные сообщения, толерантный парсинг ответа (markdown-забор,
   преамбула), пустой ответ модели ловится отдельно.
4. Качество проверено двумя инструментами: таблица 100 тест-кейсов (9 категорий:
   happy path, граничные данные, невалидный вход, выдумки, 20 промпт-инъекций, увод
   темы, контракт вывода, безопасность контента, стабильность) и прогон на 20 реальных
   товарах каталога СОЮЗ-ПРИБОР — 14 автопроверок на кейс + ИИ-судья. Метрики:
   `docs/eval-results.md`.
5. 46 автотестов (pytest, мок-транспорт, без сети и ключей) фиксируют контракты:
   валидация, ретраи, парсинг, коды ответов, «битый вход не доходит до модели».

**Сложности.**
- Модели свойственно «добивать» короткие описания до требуемых 800 символов
  правдоподобными выдумками — решилось правилом «пиши сколько получается, выдумками
  не добивай» + обязательными разделами КИП с меткой «данных нет» (по ним видно,
  каких данных не хватает).
- openai SDK 3.x работает поверх httpx2: стандартные httpx-моки (respx) его не
  перехватывают — тесты клиента написаны на нативном `httpx2.MockTransport`,
  что позволило проверять реальное поведение ретраев SDK.
- У ряда моделей «размышления» съедают лимит токенов и ответ приходит пустым —
  это отдельная ветка обработки с понятным сообщением.

**Запуск:** `pip install -r requirements.txt`, `cp .env.example .env` (вписать ключ),
`uvicorn app.main:app` → http://127.0.0.1:8000. Подробности, API-контракт,
ограничения и улучшения — в README.
